# Проверки Modular 6.9.11 — 14.11.2026

Linux, Python 3.12.14, NumPy 2.3.5, SciPy 1.17.0, FFmpeg 7.1.5.
Прямого запуска Windows 11 здесь не было.

## Автоматические проверки

87 unittest-тестов прошли; также прошли 9 исходных safety/validation-тестов
и 6 исходных микро-тестов. После последнего исправления 23 целевых
проверки восстановления, номинальных часов, реальной записи WAV и прогресса
прошли отдельно. Журналы: `TEST_LOG.txt`, `NATIVE_TEST_LOG.txt`,
`LEGACY_TEST_LOG.txt`, `LEGACY_MICRO_TEST_LOG.txt`.

Новые проверки используют настоящее аудио и подтверждают:

- Разные номинальные часы у полностью восстановленного окна больше не
  создают ложную регрессию. Прежняя схема на тестовом звуке давала разницу
  более одного отсчёта между измерениями разного времени.
- Кеш учитывает изменившийся центр эталона.
- Испорченный записанный PCM отклоняется даже при `micro_changed=false`.
- Полная сквозная проверка сохраняет удалённую полезную поправку и
  восстановленное окно; записан настоящий шестиканальный S16 WAV,
  исходник не изменён.
- Совпадение номинальных часов не скрывает отличие аудио восстановленной базы.
- Объединённые счётчики сеток сохраняют точные абсолютные диапазоны эталона,
  включая миллисекунды и использование кеша. Вывод помещается в 80 столбцов.
- Диагностика включает предложение карты и его звук после отказа до записи,
  даже если итоговый базовый WAV принят.

## Проверка присланного пакета

CRC шести ZIP и SHA-256 всех 131 восстановленного файла совпали.
По отчёту основной запуск создал WAV с базовым улучшением; новые поправки
отброшены после 12 сквозных проверок из-за одного повторяющегося окна.
Полный разбор: [FIX_20261114_RU.md](FIX_20261114_RU.md).

На десяти доступных восьмисекундных отрывках сохранены абсолютные координаты
фильма и фаза исходных сеток. Из 32 112 плотных измерений текущего отчёта
заново построены 2011 предложений локальных часов поверх сохранённой базовой
карты. Проверяются только доступные интервалы, с отступом 350 мс от краёв
вырезок; непереданные участки не считаются проверенными.

Исходная база после сравнения на одинаковом времени потребовала одной
локальной отмены. Сквозная проверка дополнительного кандидата дала
`71 → 3 → 2 → 0` отказов, сохранив 1215 отметок улучшения последнего прохода.
Все эти переходы — сравнения до записи, не готовые WAV.

После этого записаны реальные S16 WAV десяти интервалов. 5198 проверок
записанного PCM относительно исходника и защищённой базы прошли без отказов.
В 2451 сравнении подтверждено улучшение, медианный остаток таких сравнений
0,001219 мс. Использованы разные сетки и две базы сравнения, поэтому эти
числа не обозначают независимые места фильма.
Числовые результаты: `REPORT_ANALYSIS_20261114.json`.

## Ограничения области проверки

Исходного звука непосредственно около 17:08,351 в старом пакете нет.
Ошибка установлена по отчёту и числовым картам: полностью восстановленное
окно сравнивалось с базовым окном, смещённым на 1,249451 мс по эталону.
Изменение логики проверено на воспроизводимом аудиотесте с тем же условием
разных номинальных часов и идентичного восстановленного PCM.

Новый полный WAV фильма пользователя здесь не записывался. Локальные
проверки не гарантируют прохождение ещё не полученных аудиоокон.
Пороги качества, уникальности и одного отсчёта не ослаблены.

Полный 12-этапный тест на четырёхминутной синтетической паре DTS/6-channel WAV
проводился для 6.9.10; его исторический журнал явно помечен в
`FULL_PIPELINE_LOG.txt`. Это не новый полный прогон 6.9.11.
Для текущей версии выполнены интеграционные тесты микро-режима и записи
настоящих многоканальных WAV, входящие в 87 тестов.

Пользовательские аудиофрагменты, полные отчёты и личные пути в репозиторий
не публикуются. Рабочая программа заново анализирует выбранные аудиофайлы;
числовые карты пользователя использовались только при диагностике.

```text
python -m unittest discover -s tests -t . -v
python self_test_v6_8.py
python self_test_v6_9.py
```

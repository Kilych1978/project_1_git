# Исправления 6.9.8 по полному отчёту 22.10.2026

## Почему прошлый запуск оставил исходник

Все 124 файла трёх присланных диагностических архивов проверены по CRC
и SHA-256 из манифестов. В `PCM_MICRO_REPORT.json` записан результат
`BASELINE_KEPT_ERROR`: «Некорректная или немонотонная карта времени».
Проверок записанного микроуточнения не было: до записи WAV программа не дошла.

Это численный сбой при отмене локальных поправок. Две сетки времени содержали
моменты `2428.962388888888` и `2428.9623888888887` секунды — разница меньше
триллионной доли секунды. После вычисления поправки оба значения округлялись
до одного числа. Проверка принимала это за нарушение порядка времени.
Короткие тестовые фрагменты такую ошибку не выявили.

Сбой воспроизведён на полных числовых картах из отчётов. Исправление объединяет
только соседние узлы в пределах погрешности float64, когда обе координаты
различаются на эту погрешность. Концы участка и исходные кубические кривые
сохраняются. Настоящие обратные участки, плоские интервалы и монтажные скачки
по-прежнему отклоняются. Ограничения скорости и критерии качества не ослаблены.

## Как сохраняется проверенный результат

До сбоя базовый PCM-план уже прошёл предварительную проверку. Раньше исключение
в дополнительном варианте выбрасывало и этот план. Теперь он сохраняется
в памяти текущего запуска. При ошибке дополнительного поиска программа
возвращается к нему и проверяет **реально записанный WAV**. Одной успешной
предварительной проверки для выдачи результата недостаточно.

Ошибки дополнительного поиска сохраняются в `PCM_OPTIONAL_FAILURE.txt`
и `FAILED_OPTIONAL_PLAN.json`. Необработанная ошибка PCM-уточнения отражается
в статусе `BASELINE_KEPT_ERROR` и `PCM_ERROR_TRACEBACK.txt`. Новые плотные
измерения сохраняются в отчёте до построения следующей карты, чтобы сбой
не лишал диагностику уже собранных данных.

## Если улучшение не подтверждено

Новый аудиофайл не создаётся. Исходник используется напрямую, без копирования
и переименования. В консоли: **«Улучшение не подтверждено. Новый аудиофайл
не создан»**. Отчёты, графики и `REPORT_BUNDLE*.zip` сохраняются.
В итоговом JSON: `output_created: false`, `output_file: null`,
`retained_file` — путь к исходной дорожке.

Папки `pass_1–3` содержат отчёты проверок основного рендера. Отклонённые
многоканальные аудиофайлы и их проверочные PCM удаляются. Принятый основной
файл перемещается в корень папки результата. Если основная синхронизация
подтверждённо улучшила звук, её файл сохраняется даже при отказе дополнительного
микроуточнения.

## Дополнительное уточнение оставшихся отрезков

Введена вторая фаза измерений на сдвинутой сетке только около пропусков
и мест с частотным анализом. Используются новые измерения текущего входного
PCM, без чтения предыдущего результата с диска. Точки уже входят в общую
контрольную сетку; основной шаг не превращается в сплошной поиск через 1 мс.

Короткий отрезок может предлагаться по согласованным частотным измерениям
со сходством не ниже 0,95. Разрешён пропуск одного неизвестного якоря,
если соседние независимо измеренные точки подтверждают одну скорость:
интервал между ними не больше 251 мс, ошибка подгонки не больше 80 мкс.
Противоречивый якорь остаётся границей. Для предложения нужны минимум
три согласованных измерения с общей протяжённостью не меньше 200 мс.

После неё отдельно проверяется общий ход времени отрезка: используются
частотные якоря со сходством от 0,85 и интервалом не больше 501 мс.
Это более широкий источник предложений, а критерии приёмки PCM остаются
прежними. Уже принятую строгую фазу нельзя ухудшать.

Каждая такая вставка проходит прежние проверки исходных и абсолютных окон,
затем проверку записанного многоканального WAV. Первая удачная поправка
сохраняется как база дополнительной. Новые измерения и причины отказов
записаны в `phase_clock_measurements` и `phase_choice_audit` PCM-отчёта.
Ошибка дополнительной фазы сохраняется в `PCM_PHASE_FAILURE.txt`;
предыдущий проверенный план остаётся доступен для окончательной проверки.

При отказе записанного WAV отмена затрагивает все вложенные непроверенные
PCM-слои в соответствующем окне эталона. Защищённый базовый план сохраняется.
Размер отменяемого окна берётся из фактической проверки с запасом на ядро
интерполяции. Один плохой переход больше не остаётся спрятанным под верхним
слоем и не требует отказа от остальных улучшений.

Старые папки, карты и PCM не загружаются. Для дорожки после v3.3 с остаточными
миллисекундами используйте `MICRO_REFINE.cmd`: повторная крупная синхронизация
и её три полных рендера для этого режима не нужны.

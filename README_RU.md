# Universal Audio Waveform Sync — Modular 6.9.8

Эта сборка возвращает интерфейс исходной 6.9.1: прежнее меню, 12 этапов,
проценты выполнения и прежние графики. Основная синхронизация использует
её алгоритм. Дополнительно проверяется и исправляется малый остаточный
сдвиг по самим звуковым отсчётам.

Каждый запуск начинает анализ с выбранных аудиофайлов. Старые папки результата,
карты, отчёты и PCM-файлы не нужны. Рабочие данные создаются заново в папке
текущего результата; ничего переносить из удалённой сборки не требуется.

## Запуск на Windows 11

1. Распакуйте ZIP **в новую папку**, например `C:\WaveSync_6_9_8`.
2. Нужны Python 3.11 или новее и FFmpeg вместе с FFprobe.
   Рекомендуется Python 3.12 x64 с [python.org](https://www.python.org/downloads/windows/).
   Для Python 3.14 x64 также проверена доступность необходимых Windows-пакетов.
3. Можно положить `ffmpeg.exe` и `ffprobe.exe` в `tools\ffmpeg\bin` внутри
   новой папки. Альтернатива — установить FFmpeg в PATH:
   `winget install --id Gyan.FFmpeg --exact`, затем открыть новое окно CMD.
4. Один раз дважды щёлкните `SETUP_WINDOWS.cmd`. Он устанавливает библиотеки
   в локальную `.venv` и проверяет Python, FFmpeg и FFprobe.
5. Положите обе звуковые дорожки рядом со `start_sync.py`.
6. Для дорожки, уже синхронизированной версией 3.3, дважды щёлкните
   **`MICRO_REFINE.cmd`**. Он делает только PCM-уточнение: четыре этапа,
   прежние меню, процент выполнения и оценка времени до завершения.
   Для первоначальной синхронизации используйте **`START_WINDOWS.cmd`**:
   сохранены все 12 этапов 6.9.1 и её набор графиков.
7. В прежнем меню выберите эталон, затем дорожку с рассинхроном. Нумерация
   второго списка начинается заново. Подтвердите запуск анализа.
8. При полном запуске перед применением программа покажет план и попросит подтверждение `[Y/N]`.
   Введите `y`, чтобы создать отдельный результат.

В режиме микроуточнения эталон выбирается как обычно; второй дорожкой
выбирайте файл **после v3.3**.
Микропоиск охватывает остаток в пределах ±25 мс. Если рассинхрон значительно
больше, нужен полный запуск. Команда из CMD: `START_WINDOWS.cmd --micro-only`.
Дополнительное PCM-уточнение также включено в конец полного запуска.

Если установка не проходит, скопируйте её сообщение об ошибке. Проверить
только установку можно командой `START_WINDOWS.cmd --check`.

## Как сохраняются улучшения

Сначала заново вычисляется базовый PCM-вариант. Новые способы выравнивания
могут добавлять только проверенные локальные улучшения относительно него.
Для согласованных отрезков отдельно оцениваются скорость и задержка;
на их границах используется короткое плавное смешивание всех каналов.
Это помогает сохранить форму волны около резких изменений задержки.
Готовый WAV декодируется и проверяется после записи.

Около пропущенных мест выполняются новые измерения на сдвинутой сетке.
Согласованные частотные измерения и общий ход времени отрезка используются
для дополнительных предложений. Они проверяются относительно уже принятого
PCM и в записанном WAV. При локальном отказе отменяются все затронутые
непроверенные слои; подтверждённая база сохраняется.

## Повторные операции на шаге 11

Это повторная проверка всей дорожки после отмены небезопасных локальных поправок.
Теперь заголовок и проценты содержат `РЕНДЕР: ПРОХОД 1/3`, `2/3` и т. д.
После отказа показываются число расхождений и их таймкоды. Если основная карта
отменена, это обозначается отдельно; PCM-уточнение после неё работает независимо.
Его проверки также имеют номер прохода. При локальном поиске указан текущий
момент дорожки. Процент относится к показанной операции.

## Где результат

В консоли в конце указан полный путь к готовому аудиофайлу. Если основной
режим уже создал `_SYNCED.wav`, уточнение сохраняется отдельно как `_PCM_SYNCED.wav`. Отчёты лежат
в папке с окончанием `_WAVEFORM_SYNC`. Повторный запуск создаёт новую папку
с номером. Исходные дорожки и предыдущие результаты не перезаписываются.

Сохранены исходные отчёты и графики 6.9.1. Добавлены:

- `PCM_MICRO_REPORT_RU.txt` — применено ли PCM-уточнение и почему;
- `PCM_MICRO_REPORT.json` — измерения, проверки и полный план считывания PCM;
- `BASELINE_PCM_PLAN.json` — базовый вариант, рассчитанный в этом же запуске;
- `PCM_MICRO_POINTS.csv`, `PCM_MICRO_HOLDOUT.csv`, `PCM_MICRO_ACTUAL.csv` — подробные точки;
- `PCM_MICRO_REMAINING.csv` — таймкоды измеримых остатков больше 0,1 мс,
  если они есть: отдельно участки без поправки и остатки после частичной поправки;
- `14_pcm_micro_validation.jpg` — измеренный остаток до уточнения и в проверяемом файле;
- `15_pcm_waveform_overlays.jpg` — увеличенные волны эталона, исходного и готового PCM;
- `DIAGNOSTIC_CLIPS.zip` — монофрагменты первого канала эталона, основного
  результата и итогового файла с одинаковым временем начала, обычно по 8 секунд;
- `RUN_LOG.txt` — журнал всего запуска, включая сообщения об ошибках;
- `RUN_INFO.json` — версия сборки, режим, система и состояние завершения;
- **`REPORT_BUNDLE.zip`** — все отчёты, карты, таблицы, графики, журнал и короткие
  звуковые фрагменты. Архив собирается после `FINAL_SYNC_MAP.json`.
  Если всё не помещается в 25 МиБ, создаются `REPORT_BUNDLE_01.zip`,
  `REPORT_BUNDLE_02.zip` и т. д. Приложите **все** эти архивы. Каждый открывается
  самостоятельно; вручную разделять файл больше не нужно.

Если микроуточнение не подтвердило безопасное улучшение, сохраняется
подтверждённый основной результат. Если и основной алгоритм не нашёл
улучшения, новый аудиофайл **не создаётся**, исходник не копируется:
«Улучшение не подтверждено. Новый аудиофайл не создан».
Отчёты и диагностический пакет сохраняются. В итоговом JSON `output_created`
равен `false`, `output_file` равен `null`, а `retained_file` указывает на исходник.
Отклонённые WAV и их проверочные PCM из `pass_1–3` удаляются; отчёты остаются.
Принятый основной файл лежит в корне папки результата.
Если PCM-алгоритм завершился ошибкой, консоль сообщает об этом отдельно,
а подробности сохраняются в `PCM_ERROR_TRACEBACK.txt`.
Неизмеримые участки не обозначаются как идеально синхронные.

При PCM-уточнении сохраняются частота, число каналов и разрядность обычного
PCM-исходника: 16/24/32 бита, а float остаётся float. Для 48 кГц, шести каналов
и 16 бит битрейт составляет 4608 кбит/с. Фильм длиной 87:32 занимает около
2,82 ГиБ; удвоения до 32 бит больше нет. Обычный WAV используется, пока
размер позволяет; для больших файлов — RF64 с проверенными счётчиками отсчётов.
Сжатый исходник после коррекции может стать больше: повторное сжатие с потерями
не выполняется. На время работы также нужен временный многоканальный PCM.
Программа проверяет свободное место перед рендером.

Оценка `EXCELLENT` относится к крупной карте. Остаточные миллисекунды
показываются отдельно в PCM-отчёте; она не означает идеальное совпадение всех волн.

## Если результат требует дальнейшей проверки

Для разбора приложите **`REPORT_BUNDLE*.zip`** текущего запуска. В них есть
монофрагменты первого канала; полные дорожки и промежуточные PCM исключены.
Ничего автоматически не отправляется в интернет.

Для конкретных мест Audacity запустите **`DIAGNOSE_POINTS.cmd`**, выберите
эталон и сравниваемую дорожку, затем введите таймкоды через пробел, например:

```text
7:28.755 52:05.916 52:15.301
```

Этот отдельный режим последовательно декодирует первый канал, вырезает
фрагменты по точным PCM-счётчикам и создаёт диагностический пакет.
Синхронизация и многоканальный рендер не запускаются. Временные PCM удаляются.
Можно указать до восьми точек. Чтобы исследовать остаток в готовом файле,
положите его копию рядом со скриптом и выберите её второй дорожкой.
Для исследования входа выбирайте входную дорожку.
